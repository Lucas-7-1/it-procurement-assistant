# AI Coding SaaS 采购

## 最小需求字段

- 使用人群、语言/IDE/代码仓库、开发网络和设备环境。
- 主要场景：补全、问答、重构、测试、代码评审、知识库或 Agent 工作流。
- 采购席位、预计激活/周活/月活、峰值并发和推广节奏。
- SSO/SCIM、RBAC、审计、策略中心、代理/网络、私有知识库和管理 API。
- 源代码、提示词、遥测、索引和输出的敏感级别、区域、留存与训练使用要求。
- 允许的底层模型、模型切换、开源许可证与生成代码治理要求。

## 成本和价值口径

拆分席位订阅、用量加购、企业控制台、安全功能、知识库/索引、实施培训、支持和退出费用。计算：

- 每采购席位、每激活席位、每月活用户成本；
- 不同激活率下的年度成本和闲置金额；
- 试点扩容、人员流动和席位回收后的情景成本；
- 已验证的单位任务时间/质量变化。

接受率、代码行数或主观“提效”不能单独代表业务价值。只有在有基线、样本、观察期和归因边界时，才估算 ROI。

“未进入月活”不自动等于可回收闲置席位。先核对活跃口径、低频角色、休假/新入职、季节性、关键备用需求和最近多月趋势，再确定可回收数量。

## POC 与评价

- 选择有代表性的开发者、语言、仓库和任务；设置试点前基线或对照组。
- 测激活、持续使用、建议接受、任务完成时间、缺陷/返工、开发者满意度和支持负担。
- 测 SSO/SCIM、权限、审计日志、策略执行、网络兼容、IDE/仓库兼容和管理可见性。
- 用非生产或经批准的数据测试敏感代码泄漏、越权检索、秘密信息、脆弱依赖、错误许可证和不安全建议。
- 区分产品体验、底层模型能力和企业治理能力；记录模型/版本，避免结果不可复现。

## 商务、SLA 与合同重点

- 谈席位增减/回收、阶梯、并发、超额、试点转正式、季度 true-down、价格保护和续约涨幅机制。
- 定义企业功能和底层模型是否包含、模型切换/下线通知、管理平台可用性、支持响应和重大安全事件通知。
- 明确源代码/提示词/索引/遥测是否用于训练、保留多久、存在哪里、谁是子处理方、终止后如何删除和证明。
- 明确生成代码权利、第三方 IP/开源许可证风险分配、日志审计、数据导出、知识库迁移和离职/终止访问撤销。
- 供应商拒绝关键安全条款时，形成风险接受备忘录和补偿控制，不把“标准条款不可改”写成无风险。

## 运营指标

按团队/角色跟踪激活率、周活/月活、留存、单位活跃用户成本、关键场景采纳、支持工单、安全事件、模型变更和回收席位。扩容必须由持续使用和可验证价值驱动。
