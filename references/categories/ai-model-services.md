# AI 模型 / MaaS / API 采购

## 拆清供应链

先画四层关系：

1. **能力层**：底层模型及具体版本/端点。
2. **推理层**：谁提供算力、部署、限流、缓存、监控和故障恢复。
3. **渠道层**：模型原厂、云市场、聚合网关、代理/转售或集成商。
4. **合同层**：谁报价、开票、承诺 SLA、处理数据、承担侵权/中断责任。

同一底层模型由不同渠道提供时，不把“模型效果”重复评分；重点比较价格结构、容量、延迟、稳定性、数据路径、支持和责任承接。

## 最小需求字段

- 场景、调用方、业务重要性、人工替代/增强方式和成功定义。
- 模态与端点、模型/版本、区域和部署方式。
- 平均/峰值请求量、输入/输出 token、上下文长度、QPS、并发、TPM/RPM、批量或实时。
- P50/P95/P99 首 token 延迟、生成速度、超时、错误率和可用性目标。
- 数据敏感级别、日志/提示词/输出的留存、训练使用、跨境和子处理方要求。
- 质量基准集、人工评分规则、安全/内容治理要求、版本变化容忍度。
- 主供/备供、切流条件、容量爬坡和灾备要求。

## 成本归一

按真实使用链路计算，不只比较单价：

`月调用成本 = 输入 token × 输入单价 + 输出 token × 输出单价 + 缓存/批处理/图像/音频等费用 + 平台/支持/专线费 + 重试与失败浪费`

同时计算：

- 每千次成功请求成本；
- 每个业务成功任务成本；
- 低/基准/高流量情景 TCO；
- 最低承诺利用率、超量单价、未用额度损失；
- 多供应商路由、观测、集成和退出成本。

确认价格单位、token 计数规则、缓存命中、长上下文溢价、阶梯区间、免费额度、币种/税、限速和模型版本是否一致。不要拿第一家报价当市场基准。

## POC 与评价

- 使用同一版本、参数、数据集、提示词策略、时段和成功口径；保存请求 ID、时间戳和原始结果。
- 对质量采用业务基准集、盲评/双评和一致的评分锚点；区分模型能力与渠道服务能力。
- 同时测质量、成功率、P95/P99 延迟、吞吐、超时/错误、峰值稳定性、安全拦截、可观测性和单位成功任务成本。
- 进行持续/突发压测、故障与限流演练、版本升级回归和主备切流演练。
- 说明样本代表性、评审一致性和结论敏感性；小样本演示不得外推为正式履约能力。

## 商务与供应策略

- 比较按量、阶梯、预付承诺、保底/超量、包量、容量预留和企业套餐。
- 谈清 true-up/true-down、额度滚存、预测偏差、价格保护、降价跟随、模型升级是否另收费。
- 评估原厂直签、云市场、聚合商和代理的责任、毛利、账期、支持与锁定差异。
- 单供只能在可解释的独占能力、转换成本或规模经济成立时采用，并同时定义备份、退出和定期重验机制。
- 双供/多供必须定义流量份额、切流阈值、最低量、数据一致性、性能归因和季度动态调整规则。

## SLA 与合同重点

- API 可用性、错误率、限流、容量、延迟口径、计量点、排除项、事件等级、通知、服务补偿和连续不达标的退出权。
- 模型/端点下线、版本静默变化、能力退化、价格变化的通知期、兼容期和回归测试权。
- 提示词、输入、输出、日志和衍生数据的所有权、用途限制、训练 opt-out、留存/删除证明、区域和子处理方。
- 输出内容与训练数据相关的 IP/第三方索赔责任、使用限制和内容安全分工；交由法务确认最终文本。
- 可观测日志、审计证据、数据导出、迁移协助、路由配置和终止后连续服务。

## 运营指标

按模型/端点/业务场景跟踪质量、成功率、延迟、错误率、单位成功任务成本、承诺利用率、异常账单、版本漂移、主备切流和供应商整改。不要只看总体可用率。
