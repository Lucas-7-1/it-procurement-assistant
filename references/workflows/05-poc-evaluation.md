# 05 POC、评估与推荐

## 目标与边界

用既定规则和可复现证据验证候选、计算结果并提出推荐。评分卡设计属于 03；本阶段可以修正明显无法执行的锚点，但必须记录变更并在看结果前完成。

## 最小输入

已有候选、关键需求/P0 和待验证问题即可设计 POC。要作最终排名，还需实际测试/演示/审查证据和批准的评分规则。缺实际证据时只输出方案，不模拟测试结果。

## 步骤

### 1. 检查评估就绪度

确认：

- 所有候选接受相同范围、场景、数据、时限和提交格式；
- 每个标准有锚点、权重、证据和负责人；
- P0/门槛与一般评分分开；
- 测试数据经过安全/隐私批准，优先脱敏或合成；
- 版本、参数、环境、时间窗、单位和基线已固定；
- 供应商自由演示与甲方统一脚本分开记录。

### 2. 设计最小充分 POC

选取最能区分方案或暴露失败风险的关键场景。每个用例定义：

- `test_case_id`、业务目的、输入、步骤、预期、门槛和评分；
- 样本来源、代表性、重复次数/观察期和通过证据；
- 环境、版本、参数、数据、日志/截图/请求 ID；
- 失败、异常、限流、降级、恢复和退出/导出测试；
- 责任人、见证人和执行时间。

POC 周期、样本量和参考客户数量按风险与证据充分性决定，不采用通用固定值。不能做客户核验时，使用受控演示、合同承诺、运行数据或第三方审计等替代证据并降低置信度。

### 3. 执行与留痕

- 逐项记录结果和证据；供应商承诺但未实测的项标 `未验证`。
- 每个分数附锚点匹配理由。缺证据写 N/A，不给默认中间分。
- 记录评委原始分、角色、分歧和利益冲突；保留校准前后变化。
- 记录承诺与实测偏差、版本/配置变更和异常重跑原因。
- AI/云场景按品类手册同时记录质量、时延、稳定性和单位成功任务成本。

### 4. 计算和敏感性

只对通过门槛且证据充分的项目做加权计算。检查：

- 权重合计和公式；
- 缺失值、异常值和小数处理；
- 相同单位和成本情景；
- 评委分歧、重复运行方差和证据置信度；
- 权重、用量、价格、迁移成本或关键假设变化是否翻转排名。

定性重大风险可以打破同分，但必须单列为决策理由，不能伪装成计算结果。

### 5. 推荐

给出首选、备选、条件性推荐或全部不推荐。逐家说明：通过/未通过门槛、主要证据、优势、缺口、TCO/价效比、依赖、合同需锁定项和选择风险。推荐不等于授权决策。

## 输出

1. POC 范围与可复现脚本；
2. 证据矩阵和原始/汇总评分；
3. 门槛结果、差异和未验证项；
4. TCO/单位经济性比较；
5. 分歧与敏感性；
6. 排名、条件和推荐；
7. 进入商务谈判前需补证/锁定事项。

## 质量检查

- 没有把 Demo 表现外推成生产履约能力。
- 没有为缺证据格子补分。
- 没有因“必须选一家”而忽略全部不达标。
- 每个关键结论能回到用例、原始证据和计算口径。
