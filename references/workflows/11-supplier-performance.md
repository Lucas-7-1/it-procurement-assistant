# 11 供应商绩效与运营评估

## 目标与边界

用运行、使用、成本和履约证据判断供应商/服务表现，形成 QBR、整改和供应策略输入。本阶段测量过去与当前表现，不自动决定扩大合作或续约。

## 最小输入

合同/SLA、监控、工单、使用、账单或用户反馈中的任一类即可做部分评估。先报告证据覆盖；缺失维度用 N/A，不用 0 分替代。

## 步骤

### 1. 定义评估范围和基线

确认供应商/产品/区域/端点、评估期、合同目标、上期基线、业务关键时段和评价责任人。供应商报告作为输入，甲方系统数据和可验证证据优先。

### 2. 建立通用绩效框架

按项目裁剪：

- 服务质量：可用、性能、事故、容量、恢复；
- 支持与交付：首响/恢复/解决、积压、重复问题、变更和路线图；
- 使用与价值：激活、使用、核心流程、业务结果和用户反馈；
- 安全合规：事件、审计、漏洞、证书、数据处理和整改；
- 商务健康：账单准确、价格、承诺利用、合同执行和供应商健康；
- 可持续供应：团队、上游依赖、主备切换、可移植和退出准备。

### 3. 加入品类指标

- **AI 模型/API**：质量/安全漂移、版本变更、成功率、P95/P99、限流、单位成功任务成本、fallback 和主备切流。
- **AI Coding**：激活/活跃、留存、关键场景采纳、单位活跃开发者成本、安全/许可证事件、席位回收。
- **云/GPU**：单位工作负载成本、利用/闲置、承诺覆盖与利用、容量满足、出网、异常账单和 FinOps 动作。
- **SaaS**：活跃席位、关键流程、工单、API/存储超量、产品变更和冗余工具。
- **专业服务**：里程碑、缺陷/返工、工时/预算、关键人员、知识转移和分包。

### 4. 区分合同结果与业务影响

分别写：

- 合同 SLA 是否达到及条款依据；
- 即使合同达标，业务是否因高峰停机、质量漂移或限制受到影响；
- 是否构成违约由合同/法务确认，不把“体验差”直接写成法律违约。

席位产品要分开“已分配、已激活、月活/周活、低频但必要、可回收”。单月未活跃只形成回收候选，不能直接等同闲置或节省。

### 5. 评分、趋势与根因

使用公司供应商绩效规则；没有规则时给建议维度和锚点，待授权确认。每个分数附证据、覆盖率和趋势。对低分或恶化项区分产品/供应商、甲方使用、上游/共同依赖和外部事件。

### 6. 整改与治理

把问题转成 CAPA/整改项：问题、基线、目标、动作、责任人、截止、复核证据、升级/补救和剩余风险。整改周期按严重度和合同约定，不固定天数。

## 输出

1. 运营结论与证据覆盖；
2. KPI/SLA/使用/成本评分卡；
3. 合同表现与业务影响对照；
4. 趋势、根因和 Top 问题；
5. 服务积分/扣减/补救建议；
6. CAPA、QBR 议题和升级事项；
7. 对续约、份额调整、备供或退出评估的输入。

## 质量检查

- 缺数据维度为 N/A，不是 0 分。
- 没有把供应商自评当甲方结论。
- 已区分产品、服务、甲方和上游根因。
- 扩大、缩减、整改或退出建议都有趋势和证据。
