# IT 采购寻源地图（一句话版）

用户丢一句话（可附需求文档），Agent 自动完成五看三定实时寻源，交付一个离线单文件 HTML。分析细节全部进 HTML；聊天回复只给结论和文件。

## 默认动作

收到需求后静默执行，中途不停下来征求同意：

> 需求解读 → 五看实时调研 → 三定 → 构造证据化地图数据 → 生成 HTML → 简要结论

仅当一句话连采购品类都无法识别时，才问一个阻断性问题。其他信息缺口一律用显式假设（写入 `assumptions`）或“待确认”覆盖，不问用户。

## 1. 需求解读（内部完成）

从一句话中提取：采购对象、品类、规模/用户线索、地域、紧迫度、隐含约束。缺失项按该品类常见情景推断合理默认值，全部记入 `assumptions`，格式为“假设：……（依据/影响）”。附带需求文档时，以文档事实优先，文档未写明的仍按假设处理。

不补默认预算、SLA 或合规等级当事实用；假设只用于让调研继续，不当作已确认边界。

## 2. 五看实时调研

使用当时可用的联网研究能力，只采信可回链的公开证据。优先级：监管机构、标准组织、政府公示、厂商正式资料、公开财报、公开招投标、可核验客户案例；分析师与媒体作补充交叉；厂商新闻稿不单独作证据。规则：

- 每条关键事实记录来源、日期、URL；厂商自述标 `vendor_claim`。
- 查不到写“待验证”，不写“无异常”；不用模型记忆伪造玩家、份额、价格。
- 不把用户内部敏感信息提交到公开网络；只检索公开主体与公开事实。

五看覆盖要求：

- **看行业**：行业结构与竞争格局、驱动因素、供应风险。必须含两个子项：
  - **国家政策**：监管、标准、补贴/专项、信创与国产化要求、数据与安全法规；
  - **技术趋势**：技术路线演进、代际切换、生态变化及对本品类采购时点的影响。
- **看市场**：细分方式、采购/部署模式、玩家类型、计费与价格信号、格局变化。
- **看客户**：同行/友商类客户的公开采用路径、落地前提、实施与迁移方式、踩坑信号。
- **看竞争**：竞品产品对比、行业玩家全景、目标客群、技术路径差异、替代与合作关系；共享同一上游/集团的品牌要标共同依赖。
- **看自己**：基于这一句话和已知上下文，评估现有系统、团队能力、数据/合规约束、迁移与运维承受度；信息不足时写明“待确认”及影响。

## 3. 三定

在五看证据之上给出采购立场，作为 HTML 的决策结论：

- **定控制点**：本次采购最稀缺、最难替代、必须抓在手里的抓手（如单位经济性、数据主权、退出权、关键容量、生态兼容），说明为什么。
- **定目标**：本轮寻源要达成的可衡量目标（候选数量级、时间窗、成本/质量/风险目标、进入下一阶段的条件）。
- **定策略**：寻源与竞争策略（竞争性比选/单一来源论证/双供/先 POC 后扩量等）与 3–5 个关键动作、顺序和验证重点。

三定必须能回溯到五看证据；证据不足的判断标“待验证”，不写成既定事实。

## 4. 构造地图数据

生成前完整读取 [五看与供应商地图数据规范](references/five-looks-and-map-schema.md)，按该规范构造 UTF-8 JSON：

- 顶层必须含 `demand_oneliner`（用户原话）、`assumptions`、`five_looks`（看行业须带“国家政策”“技术趋势”highlights）、`three_decisions`、`sources`。
- 每个来源有唯一 source ID、标题、主体、日期、URL 或可定位出处；自述标 `vendor_claim`。
- 只有具备可回链证据、坐标依据及坐标来源的玩家才能进 `vendors`，并标 `shortlist`/`watch`/`exclude`；证据不足的只进 `pending_verification_vendors`。
- 没有联网能力或公开证据不足时，构造“待验证地图”：`vendors` 留空，候选进待验证区，五看和三定照常基于可得信息给出并标注置信度。

## 5. 生成 HTML

把 JSON 保存到可写目录后运行（以脚本实际所在 Skill 目录解析路径）：

```bash
python scripts/render_supplier_map.py supplier-map-data.json --output "寻源地图-<品类>-<YYYYMMDD>.html"
```

先修正脚本报告的校验错误再生成；不得为通过校验编造来源或坐标依据。HTML 为离线单文件，不依赖外部资源。

## 6. 回复（从简）

聊天回复控制在几行内，全部细节进 HTML：

1. 寻源结论 1–3 句：优先关注的技术路径/玩家类型、短名单前三、最大风险。
2. HTML 文件链接：`[寻源地图 HTML](</绝对路径/寻源地图-品类-YYYYMMDD.html>)`。
3. 关键假设与待确认合计不超过 3 行。

不输出方法论讲解、三段式长报告或过程自述。用户追问细节、换地域、调整边界或继续比较时，复用已有来源与已验证玩家，只研究变化部分并重新生成 HTML。

## 质量底线

- 不凭记忆生成厂商、客户案例、能力、价格、份额、格局或坐标。
- 不把供应商宣传当独立事实；明确标注 `vendor_claim`。
- 不用单一厂商来源证明市场格局。
- 不给无法回链来源和日期的事实性结论；不用伪精确数字。
- 坐标是分析定位，不是市场排名、份额或能力评分。
- 短名单不是定标结论；最终选择仍需 POC、演示、客户背调、商务和合规核验。
- 假设与事实分开：用户没说过的边界条件只能出现在 `assumptions` 或“待确认”。
